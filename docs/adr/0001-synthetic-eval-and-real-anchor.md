# 0001 - 合成评测集与可选真实锚点验证

Date: 2026-09-28

## Status

Accepted

## Context

PromptOpt v2 的核心承诺是"用户只输入提示词即可"：评测集必须由 Harness Builder AI 合成（经 p¹ 方差过滤提纯）。但这构成自证循环——AI 造题、AI 评估、AI 优化，同一模型族的偏差会原样通过 p¹ 过滤与人工检查点（它们只能提纯与纠错，不能纠偏）。V6 的 held-out 验证若也使用同一合成分布的保留集，等于用嫌疑人的证词给嫌疑人作证，防护是伪的。

## Decision

采用**可选真实锚点**策略：

1. 优化过程全量使用合成评测集（保住"零门槛"全托管体验）
2. 最终 verify（V6）强引导用户提供 3~5 条真实样本作为**锚点验证集**——它是唯一可信的最终闸门
3. 锚点仅用于最终验证，**永不进入优化循环**（保持其对合成分布的独立性）
4. 用户拒绝提供时降级为合成保留集验证，报告必须明确标注"结论未经真实数据验证"

## Consequences

### Positive

* "零门槛"与"可信验证"解耦：合成集负责驱动优化，真实锚点负责背书结论
* 已有"导入自有数据"机制可直接升格，实现成本低
* 诚实度可传递：报告读者能明确知道结论的可信边界

### Negative

* 不提供锚点的用户得到的是"未经真实验证的优化结果"，产品需要管理该预期
* 锚点样本太少（3~5 条）时统计效力有限，只能发现方向性错误

## Alternatives Considered

* **双模型交叉合成**（优化用 GPT、合成用 Claude）：成本翻倍且只是换一双"眼镜"，同族偏差无法排除
* **接受局限不防护**：仅声明合成集局限——诚实但防护为零
* **强制用户提供数据**：可信度最高但破坏"输入提示词即可"的核心承诺
